# Rageborn Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A warrior-only WoW Forever addon that shows procs, reminders and active cooldowns as styled on-screen alerts, glows the matching action buttons (macros included), and offers a page of ready-made macros.

**Architecture:** One addon folder, plain Lua 5.1, no libraries. Alerts are data (`Data.lua`); `Detect.lua` is the only file that reads game state and never lets a secret value escape; `Engine.lua` turns reads and events into "alert shown / hidden" and notifies subscribers (`Alerts.lua` draws on screen, `Glow.lua` lights buttons). Styles and glow kinds are builder functions registered in catalogs.

**Tech Stack:** Lua 5.1 (WoW Forever client, Interface 16001); system `lua5.1` for tests; Python 3 standard library only for texture generation; headless Chrome only to rasterise the icon.

**Spec:** `docs/superpowers/specs/2026-11-18-warrior-procs-design.md` — read it before any task.

## Global Constraints

- TOC: `## Interface: 16001`, `## AllowLoadGameType: camelot`, `## SavedVariables: RagebornDB`, `## IconTexture: Interface\AddOns\Rageborn\Media\icon`.
- Addon folder `Rageborn/`; every file starts `local ADDON, ns = ...`; nothing is put in `_G` except `RagebornDB`, `SLASH_RAGEBORN1 = "/rb"`, `SLASH_RAGEBORN2 = "/rageborn"` and the compartment function `Rageborn_OnCompartmentClick`.
- No libraries. No code or textures copied from any installed addon; file IDs and spell IDs are facts and may be read from them.
- If the player's class is not `WARRIOR`, `Init.lua` registers nothing and creates no frames.
- Never register `COMBAT_LOG_EVENT_UNFILTERED`. Never call Blizzard glow functions on action buttons. Never create, move, show or hide a protected frame in combat; our frames are never protected and never parented with `SetAllPoints` changes in combat to secure buttons other than at creation.
- Never pass `"TRILINEAR"` to any texture call.
- Every value read from the game goes through `ns.U.Clean` before comparison or arithmetic.
- Sounds are game sound-kit IDs only (`PlaySound`), never files.
- All user-visible text comes from `ns.L` (`Locale.lua`, enUS).
- Tests: `lua5.1 tests/run.lua` must print `ALL PASS` before every commit.
- Deploy: `./deploy.sh` copies `Rageborn/` (and `RagebornProbe/` while it exists) to `/mnt/c/Program Files (x86)/World of Warcraft/_forever_/Interface/AddOns/`.

## Review Focus

1. A secret value arrives where a number or boolean is expected (any read in combat) → no Lua error; the alert keeps its last state. *(Tests in Task 2 and Task 5.)*
2. Saved settings from an older version: missing keys, an alert key that no longer exists, a character pointing at a deleted profile → loads with defaults filled in, unknown keys ignored, character falls back to its own profile. *(Task 3.)*
3. Macro text with conditions, rank suffixes, `/castsequence` with `reset=`, `#showtooltip`, blank lines, trailing semicolons, non-ASCII spell names → correct spell list, no error. *(Task 9.)*
4. A spell the character has not learned, or a rank table where only a low rank is known → the alert does not exist for this character; the highest known rank is used. *(Task 4.)*
5. Something changes in combat that we may not act on (bars re-laid out, macro creation, profile switch) → deferred until `PLAYER_REGEN_ENABLED`, with a chat message for the user-initiated ones. *(Task 9 and Task 11.)*
